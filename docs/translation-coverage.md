# 翻译扫描记录

## 汉化工具 0.0.4：T3 Code 0.1.10

验证日期：2026-11-17。Windows 桌面应用版本为 `0.1.10`，构建提交为 `7d32075e3757`，原始 `server.asar` 的 SHA256 为 `7f23a14ce1cfdbd57973b3b388c05b3f22792219eb5e4d4ed987c6ec076b6b7d`。

### 漏译原因与修复

旧补丁在此构建上已替换 6683 处，但漏掉了新版语言目录、标题渲染和快捷键文件迁移：

- 设置页开始读取 `en-<hash>.js` 中按消息哈希索引的语言目录。旧规则不识别哈希键以及提取到变量的译文，因此包括设置分类、语言选项在内的文字仍显示英文。新版仅翻译默认导出目录中已识别的显示字符串，保留消息哈希、模块导出名称和技术标识。
- 用户的设置页截图进一步证明：默认英语模式的标题函数直接返回源文本，不一定读取语言目录。第一轮只验证目录中的 72 条消息，遗漏了这条渲染分支，导致说明已中文化、导航和标题仍为英文。修正后，在 `SettingsPanels`、`settingsSearch`、`_chat.settings` 三个文件内精确匹配这 72 条源消息；保持路由、设置键及其他文件不变。新增回归测试先复现英文输出，再验证中文输出，并使用真实资源的路由表达式和实际消息包装函数验证默认英语分支。
- 快捷键名称函数从 `KeybindingsSettings.logic` 移至 `settingsSearch`，旧规则按文件名选择函数。新版跨界面文件按内容定位，并要求唯一匹配。

同时新增 133 条词典条目，涵盖连接审批、语音设置、CSS 编辑、消息发送及项目拖放提示。词典共 5135 条。

## 验证方法

运行 `npm run check`、`npm test`、`npm run pack:check`，并分别执行：

```sh
node tools/build-dict.mjs <对应版本的原始-server.asar> --untranslated <本地报告路径>
```

完整资源验证会重新解析已翻译的 JavaScript，并核对重建后所有非替换资源与原始字节一致。回归测试检查 TSV 与 JSON 同步、插值的数量和顺序、间接文案匹配，以及模型名、路由和协议状态值的保留。

## 覆盖边界

这不是逐屏交互验收，也不代表 100% 的英文都应替换。扫描器仍分别报告 925 / 926 个未收录的独立候选字符串，其中包含品牌名、命令、路径、CSS、协议标识、第三方库错误及工具协议说明，不能将此数字直接当作界面漏译数量。

终端输出、模型回答、仓库文件、用户内容和服务端返回的动态文案不会通过替换前端固定字符串自动翻译。仍需根据具体页面和上下文继续补充；无法确认用途的技术字符串保持原样。

本次资源验证仅覆盖上表两份 Windows 构建，不代表所有平台或相同版本号的其他构建已经完成验证。修改未自动应用到已安装的 T3 Code，也未发布到 npm。
